# 参与贡献 / Contributing

感谢你帮助改进 GitSwitch。提交改动前，请保持变更聚焦，并确认文档、实现和测试描述的是同一项行为。

Thank you for helping improve GitSwitch. Keep changes focused, and make sure the documentation, implementation, and tests describe the same behavior.

## 开发环境

- macOS 15.0 或更高版本
- Xcode 26 或更高版本
- [XcodeGen](https://github.com/yonaskolb/XcodeGen)
- [GitHub CLI](https://cli.github.com/)

```bash
git clone https://github.com/Aenvo/GitSwitch.git
cd GitSwitch
brew install xcodegen gh
./scripts/test.sh
```

`project.yml` 是 Xcode 工程配置的来源。`GitSwitch.xcodeproj` 由 XcodeGen 生成，不应提交。

可选地安装 [pre-commit](https://pre-commit.com/) 并启用仓库自带的 Gitleaks 检查：

```bash
brew install pre-commit
pre-commit install
```

## 修改边界

- 主应用负责调用 `gh`、切换账号和修改全局 Git 身份；Widget 只读取回环状态并打开主应用。
- 状态服务必须只绑定 `127.0.0.1:47831`，响应不得包含凭据。
- 调用外部命令时使用 `Foundation.Process` 和参数数组，不拼接 shell 命令。
- 不要把 GitHub token、钥匙串内容、真实账号、个人提交邮箱或本机绝对路径写入源码、测试、日志或文档。
- 不要提交 `build/`、DerivedData、生成的 Xcode 工程、应用包或签名材料。

## 验证

普通改动至少运行：

```bash
./scripts/test.sh
```

只有修改账号切换、命令参数、验证或回滚逻辑时，才需要实机双账号测试。该测试会修改真实 `gh` 账号与全局 Git 身份，账号信息必须通过 `GITSWITCH_LIVE_ACCOUNT_1_*` 和 `GITSWITCH_LIVE_ACCOUNT_2_*` 环境变量提供。测试结束后，无论成功或失败，都要手动核对并恢复实际状态。

Pull Request 应说明：

- 解决的问题和用户可见影响
- 关键实现边界或兼容性影响
- 实际运行的验证命令及结果
- 尚未执行的 macOS、Widget、签名或实机验证

安全问题请按 [安全政策](SECURITY.md) 私密报告，不要在公开 Issue 中披露未修复漏洞。

## Development setup

- macOS 15.0 or later
- Xcode 26 or later
- [XcodeGen](https://github.com/yonaskolb/XcodeGen)
- [GitHub CLI](https://cli.github.com/)

`project.yml` is the source of truth for the Xcode project. `GitSwitch.xcodeproj` is generated by XcodeGen and should not be committed. Contributors may optionally install [pre-commit](https://pre-commit.com/) and run `pre-commit install` to enable the repository's Gitleaks hook locally.

## Change boundaries

- The main app invokes `gh`, switches accounts, and updates the global Git identity. The widget only reads loopback status and opens the main app.
- The status service must bind only to `127.0.0.1:47831`, and responses must not contain credentials.
- Invoke external tools with `Foundation.Process` and argument arrays rather than shell command construction.
- Do not add GitHub tokens, Keychain contents, real accounts, personal commit emails, or machine-specific absolute paths to source, tests, logs, or documentation.
- Do not commit `build/`, DerivedData, generated Xcode projects, application packages, or signing material.

## Verification

Run `./scripts/test.sh` for regular changes. Use the live two-account test only for account-switching, command-argument, verification, or rollback changes. Supply account data through the `GITSWITCH_LIVE_ACCOUNT_1_*` and `GITSWITCH_LIVE_ACCOUNT_2_*` environment variables, then manually verify and restore the real state whether the test passes or fails.

A Pull Request should state the problem and user-visible effect, important compatibility boundaries, the commands actually run, their results, and any macOS, widget, signing, or live verification that was not performed.

Follow the [security policy](SECURITY.md) for private vulnerability reports. Do not disclose an unpatched vulnerability in a public Issue.
